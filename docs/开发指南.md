## 1. 环境搭建

### Python 版本要求

- Python ≥ 3.9

### 推荐使用虚拟环境

```bash
python -m venv venv
```

激活虚拟环境：

- Windows：`venv\Scripts\activate`
- macOS / Linux：`source venv/bin/activate`

### 安装依赖

```bash
pip install -r requirements.txt
```

### 按方向安装（可选）

如只需某一方向的依赖，可按需安装：

```bash
# 数据获取
pip install requests beautifulsoup4 sqlalchemy

# 数据处理
pip install numpy pandas scipy scikit-learn

# 数据可视化
pip install matplotlib seaborn plotly

# 分析建模
pip install scikit-learn statsmodels prophet scipy ydata-profiling

# 综合应用
pip install jieba wordcloud snownlp fpdf2 openpyxl nbformat
```

## 2. 编码规范

### 路径处理

- 使用 `pathlib.Path` 处理所有文件路径，**禁止硬编码绝对路径**

```python
from pathlib import Path

data_path = Path(__file__).parent / "data" / "example.csv"
```

### 文件命名

- 格式：`{序号}_{功能描述}.py`
- 示例：`1_创建一个单位矩阵.py`、`3_数据透视表.py`

### 数据来源注释

- 每个文件开头必须标注数据来源：

```python
# 数据来源: sklearn内置数据集
```

```python
# 数据来源: https://example.com/dataset
```

```python
# 数据来源: 脚本内自建数据
```

### 版本要求注释

- 每个方向第一个文件需标注依赖库最低版本要求：

```python
# 依赖库最低版本要求: numpy>=1.21.0, pandas>=1.3.0
```

### 弃用标注

- 使用 `[已弃用]` 标注已弃用的代码或方法，并给出替代方案：

```python
# [已弃用] pd.append() 已在 pandas 2.0 中移除，请使用 pd.concat() 替代
```

### 中文支持

- 使用 matplotlib 时需设置中文字体：

```python
import matplotlib.pyplot as plt

plt.rcParams['font.sans-serif'] = ['SimHei']
plt.rcParams['axes.unicode_minus'] = False
```

## 3. 运行方式

### 单个案例

```bash
python "02_数据处理/01_NumPy/1_创建一个单位矩阵.py"
```

### 注意事项

- **网络连接**：部分案例需要网络连接，如爬虫方向、使用 `yfinance` 获取金融数据的案例
- **数据来源**：大部分案例使用内置数据集（如 `sklearn.datasets`）或脚本内自建数据，无需额外下载数据文件
- **运行目录**：请在项目根目录下运行脚本，以确保相对路径正确

## 4. 贡献指南

### 新增案例规范

1. **文件命名**：遵循 `{序号}_{功能描述}.py` 格式
2. **注释要求**：
   - 文件开头标注数据来源：`# 数据来源: xxx`
   - 关键步骤添加中文注释说明
3. **数据来源标注**：必须明确标注数据来源（内置数据集 / 自建数据 / 网络数据）

### 代码风格

- 使用**中文注释**，确保可读性
- 使用 `pathlib.Path` 处理路径
- 使用 `print()` 输出结果，便于命令行查看
- 保持代码简洁，单个文件聚焦一个知识点

### 目录规范

- 格式：`{序号}_{方向名}/{子序号}_{子方向名}/`
- 示例：`02_数据处理/01_NumPy/`、`03_数据可视化/02_Seaborn/`

### PR 流程

1. **Fork** 本仓库到个人账号
2. **Branch**：从 `main` 分支创建功能分支，命名如 `feature/xxx` 或 `fix/xxx`
3. **Commit**：提交代码，commit 信息清晰描述变更内容
4. **PR**：向本仓库 `main` 分支提交 Pull Request，描述变更内容与目的
